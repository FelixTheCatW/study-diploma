# AGENTS.md

## Проект

Дипломный проект: «Анализ пищевого поведения и прогнозирование показателей питания и веса».

Основные исходники:

- `d:\study\ml\study-ml` — подготовка данных; регрессия изменения веса (архивный отрицательный результат);
- `d:\study\ml\block07_exam_project` — подготовка данных и таблицы; классификация приёмов (архивный бенчмарк);
- `d:\study\diploma` — дипломный репозиторий и документация.

## Продуктовое решение

- Продуктовый сценарий: кластеризация приёмов пищи → паттерн питания → нутриентный профиль → риск-флаги → 2–3 рекомендации.
- ML-ядро: unsupervised clustering на уровне приёма пищи (15 322 наблюдения); внешние метки не используются.
- Признаки: доли БЖУ (CLR/ILR), энергоплотность, нутриентная плотность на 100 ккал; препроцессинг внутри Pipeline.
- Валидация: внутренние метрики, bootstrap ARI, экспертная интерпретация 50–100 приёмов; accuracy не используется.
- Фото — вспомогательный research-трек: CLIP-эмбеддинги на 2–5 тыс. приёмов, ARI/NMI с нутриентными кластерами, retrieval. Не продуктовое распознавание, не оценка порции/калорий.
- Классификация типа приёма, прогноз веса, кластеризация пользователей как привычек, распознавание блюд и оценка порции по фото, медицинские рекомендации — вне продукта.
- Все отвергнутые варианты и условия возврата: `d:\study\diploma\docs\Отвергнутые_варианты.docx`. Без новых данных к ним не возвращаться.

## Данные и качество

- Фотографии приёмов лежат в `d:\study\data\DietDiary\` (26 902 файла); в core-модели не используются, допустимы в research-треке (CLIP); сырые фото в публикацию не включаются.
- Пропуски нутриентов нельзя заменять нулём: «неизвестно» ≠ «ноль». Нужны `min_count`, missing-индикаторы и явная импутация.
- Текущий пайплайн (`groupby.sum`, `fillna(0)`) неявно обнуляет пропуски по сахарам, холестерину, клетчатке и другим нутриентам. Это методическая ошибка, её нужно исправить до кластеризации.
- Для каждой группы признаков фиксировать coverage и долю пропусков; в отчётах показывать, какие признаки и наблюдения затронуты.

## Стиль общения

- Никаких вежливых прелюдий, комплиментов и смягчающих формулировок. Оценивать жёстко и по делу.
- Критиковать артефакты и решения: код, данные, постановку задачи, метрики, архитектуру, тесты, документацию.
- Не переходить на личности и не оскорблять автора. Претензии — к работе, а не к человеку.
- Использовать профессиональную терминологию и жаргон: data leakage, target leakage, group split, baseline, pipeline, cross-validation, overfitting, class imbalance, calibration, feature importance, reproducibility и т.п.
- Если решение слабое, ошибочное или недоказанное — говорить прямо, с указанием причины и конкретного способа исправления.
- Не выдавать предположения за факты. Если данных или отчётов нет — фиксировать это как пробел.
- Не хвалить за формальное наличие файлов. Оценивать проверяемый результат: работающий код, корректный split, воспроизводимые метрики, тесты, документацию.
- В чате допустима крепкая лексика для эмоциональной окраски; в файлах проекта, README, отчётах и коммитах — только сдержанный профессиональный язык.

## Команды

- Установка: `uv sync --extra dev`
- Тесты: `uv run pytest -q`
- Lint: `uv run ruff check src tests`
- Автоисправление: `uv run ruff check --fix src tests`
- Форматирование: `uv run ruff format src tests`
- Подготовка данных: `uv run python -m src.prepare --force`
- Кластеризация: `uv run python -m src.cluster --bootstrap 30`
- Интерпретация: `uv run python -m src.interpretation`
- Sensitivity: `uv run python -m src.sensitivity`
- Экспертная разметка: `uv run python -m src.expert_validation --evaluate`
  (после заполнения `label_template.csv`)

После правок Python-кода запускать `ruff check` и `pytest`. Не коммитить без
явного указания.
